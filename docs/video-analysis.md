# Конвейер анализа видео

Обновлено: 2026-08-14. Код и артефакты — в `analysis/` (окружение: `analysis/.venv`,
Python + OpenCV). Статус: пилот пройден, весь архив просканирован и отсмотрен
(отчёты — `analysis/review/`, сводка — раздел «Итоги отсмотра архива»).

Цель: алгоритмически сократить десятки часов съёмки до посильного для отсмотра
набора кропов-кандидатов с геопривязкой, ничего не потеряв. Приоритетное
направление — линия падения ниже точки рюкзака (4663 м): участок ниже 4529 м
не осматривался (`docs/nakhodki/README.md`); несмотренный коридор посчитан
внешней группой — от 39.485139, 73.585417 (4466 м) вниз 1,95 км до 4150 м
(`docs/nezavisimyy-analiz/01-probel-pokrytiya.md`, KML —
`docs/nakhodki/search_vectors.kml`).

## Слои конвейера

Каждый слой сокращает объём для следующего. Полный кадр 1080p для визуальной
модели бесполезен (объект — единицы пикселей), поэтому машинная математика
ищет «не снег и не камень», а визуальный разбор работает только по кропам.

1. **Геоиндекс.** Для каждой секунды каждого видео — позиция дрона, углы камеры,
   зум. `scripts/dji_meta_gps.py` пишет в сайдкар GPS, высоты (MSL и
   относительную) и углы борта и подвеса; gb_yaw/gb_pitch сверены покадрово с
   волонтёрской выгрузкой `data/telegram/general/1141.zip` (медиана расхождения
   0°, максимум 2.4° на быстрых поворотах). Сайдкары, сгенерированные до
   14.08, углов не содержат — перегенерировать тем же скриптом. Зум/фокусное из
   метаданных ненадёжны — восстанавливаются самокалибровкой по видео (сдвиг
   картинки, делённый на поворот подвеса, на зависаниях), методика —
   `docs/focal-length-calibration.md`. Проекция взгляда
   камеры на рельеф (модель высот Copernicus GLO-30) даёт: карту покрытия
   (что осмотрено/не осмотрено), выборку «все кадры, где видна точка X»,
   координаты для любого кандидата.
2. **Отбор кадров.** 1–3 кадра/сек, отбрасывание смазанных и статичных
   (дрон висит — видно по телеметрии). Приоритетные участки — покадрово.
3. **CV-предфильтр** (`analysis/detect.py`, `analysis/video_scan.py`).
   Палитра кадра — 3D-гистограмма Lab; аномалия — связное пятно пикселей из
   редких ячеек, score — суммарная редкость пятна. Повторы одного места между
   сэмплами склеиваются в трек (с компенсацией сдвига сцены), на трек — один
   кроп с лучшим score. Выход — кропы, монтажные листы 6×6, `tracks.tsv`
   (таймкоды, bbox, score, GPS из сайдкара). Калибровка порогов: подтверждённые
   находки обязаны проходить, «отклонённые» из TG — материал для оценки шума.
4. **VLM-триаж.** Кропы монтируются в сетки с подписями, отсматриваются агентом
   (сабагентами), ранжирование по шкале штаба 1–5.
5. **Склейка и сравнение.** Кадры одного места из разных пролётов совмещаются
   по общим точкам (feature matching + гомография): склейка крупных планов
   в общий вид, разница между пролётами (шевеление ткани, изменения).
6. **Траектория падения.** Линия наибыстрейшего спуска от рюкзака по модели
   высот + коридор; пересечение с картой покрытия → список «видео+таймкод»,
   где коридор виден, и дыры для доснятия штабом.

Формат кандидата (по инструкции штаба): файл, таймкод, координаты, скриншот,
описание, уверенность 1–5, нужен ли повторный облёт. Сомнительное фиксируется
всегда, отсев — при сведении.

## Пилот: валидация на известных находках

Подход подтверждаем на том, что уже найдено (эталоны — `docs/nakhodki/README.md`):

| Эталон | Видео | Таймкод |
|---|---|---|
| Белый стакан с красной маркировкой | `DJI_20260813183004_0001_Z.MP4` | 3:40 |
| Бирюзовая крышка + синий фрагмент | `DJI_20260813183727_0015_Z.MP4` | 3:32 |
| Палка/крышка (зависание, 28 м) | `DJI_20260813183534_0014_Z.MP4` | 0:31 |
| Синий рюкзак | `helicopter/C0049.MP4` | 0:15–0:21 |
| Палки, крышка крупным планом | JPG `…183028_0002`, `…183101_0008`, `…183140_0012` | — |

Критерии успеха:

- Детектор помечает все эталонные объекты на кадрах, где их видит человек
  (пропуск эталона = провал, порог ослабляется).
- Объём кропов с полного видео посилен для VLM-отсмотра
  (ориентир: сокращение ≥50× против сплошного покадрового просмотра).
- VLM-отсмотр кропов отличает эталоны от шума (камни, наледь, лишайники).

объяснение — свежий камнепад (у камней тоже борозды); против него — «ткань»
и повторяемость между днями.

DEM-трассировка (SRTM 30 м, кэш `analysis/pilot/dem-cache.json`, картинка
`analysis/zone-descent-paths.png`): линии наискорейшего спуска от всех пяти
точек зоны проходят в 7–30 м от подтверждённых вещей (рюкзак, палка+крышка,
стакан, оранжевая куртка/спальник) — в пределах погрешности DEM и GPS.

зоны — GPS дрона, не объектов; наискорейший спуск — приближение (предметы
скачут и уходят дальше); зона — не единственный возможный источник вещей,
но единственная, где на линии питания кулуара сходятся визуальные аномалии.
Статус: зона лежит на линии падения найденных вещей — приоритет №1 на облёт.

## Цветовые сигнатуры найденных вещей

Слой 3 дополнен цветовой разметкой. Цвета пяти найденных вещей и восьми типовых
ловушек (охра, жёлтая корка, тень, пересвет) измерены по кадрам, которые лежат в
репозитории (`analysis/measure_signatures.py`, данные в `analysis/signatures.tsv`);
`analysis/rank_by_signature.py` дописывает к выдаче детектора колонки «расстояние
до ближайшей вещи» и «до ближайшей ловушки», не меняя порядок строк и не удаляя
кандидатов (пересортировка — только явным ключом `--пересортировать`; по замерам
она топит предметы неизвестного цвета, а цвета курток группы неизвестны). Метод,
проверка на эталонах, поведение на известных ложных срабатываниях и пределы
калибровки на пяти предметах: `docs/colour-signatures.md`.
