# alp-finder

Поисково-аналитический проект: помощь штабу поисковой операции на пике Курумды (Кыргызстан) в отсмотре съёмок с дрона и вертолёта. Три альпиниста пропали при спуске после восхождения 2 августа 2026. Задача проекта — алгоритмическая предобработка десятков часов видео и выявление подозрительных кадров (люди, снаряжение, следы, палатки, верёвки) для передачи координат штабу.

**Это не учебный проект. От скорости и качества работы может зависеть жизнь людей.** Любая находка перепроверяется перед передачей штабу; ложные срабатывания тратят ресурс спасателей, пропущенные кадры — хуже.

## Контекст операции

Подробности: `docs/operation-context.md`. Ключевое:

- Район: пик Курумды (6096 м), Чон-Алайский хребет, восточнее пика Ленина.
- Критичный неосмотренный участок: между лагерями 2 и 3.
- Штаб выкладывает съёмку в общий Google Drive, контакты штаба в `docs/operation-context.md`.

## Структура проекта

```

  operation-context.md  — факты об операции, районе, группе, контакты
  drive-inventory.md    — полная опись Google Drive (id файлов, размеры, заметки)
  telegram/             — база знаний из TG-группы волонтёров, поддиректория на тему группы (см. telegram/README.md)
    svodka.md           — сводка находок и статусов по группе, обновлять при разборе
  nakhodki/             — реестр находок с координатами, кадрами (frames/), картой и KML для штаба
  video-analysis.md     — конвейер анализа видео и статус пилота
  geoindeks.md          - геопривязка: пиксель в координату, координата в кадры, покрытие; проверка на эталонах
analysis/               — код и артефакты анализа видео (venv, детектор, кропы); план — docs/video-analysis.md
  georef.py             - рельеф, телеметрия, трассировка луча, оценка погрешности
  selfcal.py            - фокусное расстояние из самой съёмки (в метаданных его нет)
  geoindex.py           - CLI геоиндекса: tochka / kadry / pokrytie
  test_geoindex.py      - тесты на синтетической геометрии, видео и DEM не нужны
data/dem/               - модель высот Copernicus GLO-30 (scripts/download_dem.sh), в репо не хранится
data/drive/             — локальное зеркало Drive: <дата>/<слаг-папки>/<файл>
data/telegram/          — медиа из TG-группы: <слаг-темы>/<msg_id>_<файл>
logs/                   — tg-updates.log (что и когда докачано из TG), tg-watch.log (служебный)
scripts/
  manifest.tsv          — манифест скачивания: локальный путь, drive file id, размер
  download_drive.sh     — идемпотентная докачка по манифесту
  download_dem.sh       - модель высот Copernicus GLO-30 для геопривязки (37 МБ, без регистрации)
  drive_cron.sh         — ежечасный повтор докачки Drive (квоты Google); стоит в crontab
  tg_export.py          — выгрузка TG-группы (Telethon; сессия .tg_session — секрет, не публиковать)
  tg_cron.sh            — итерация докачки TG; стоит в crontab раз в минуту
```

## Данные

- Источник: общая папка Drive `1uD9uCzOm9e2GdKYiOO2Jp3GVvE8Cn3XX` (папки по датам). Доступ на чтение — публичный и через gdrive-коннектор.
- Локальное зеркало наполняется скриптом: `bash scripts/download_drive.sh` — качает по `scripts/manifest.tsv`, уже скачанные файлы (совпал размер) пропускает. При появлении новых файлов на Drive: обновить опись в `docs/drive-inventory.md`, дописать строки в манифест, перезапустить скрипт.
- SRT-файлы рядом с видео — телеметрия DJI: GPS, высота, параметры камеры на каждый кадр. Использовать для геопривязки кадров.
- Папки «Покадровый просмотр» на Drive (кадры, нарезанные волонтёрами) не скачиваются: кадры извлекаем сами из исходников; их разметка полезна как референс калибровки.
- Второй источник — Telegram-группа волонтёров «Анализ видео с дронам» (темы: новые скриншоты, гипотезы, подтверждённые/отклонённые кандидаты, инструкции). Выгрузка: `python scripts/tg_export.py` после разового логина (`--login`, нужны TG_API_ID/TG_API_HASH с my.telegram.org). Инструкция волонтёрам по отсмотру — `docs/telegram/instrukcii-i-ssylki/2026-08-12-instrukciya-prosmotra.md`, «отклонённые» — готовый набор ложных срабатываний для калибровки.

## Правила работы

- Сначала инвентаризация и документирование, потом обработка: каждое видео должно иметь запись в описи (что снято, какой участок, есть ли телеметрия).
- Все выводы рисерчей фиксировать в `docs/` — проект рассчитан на много сессий, контекст живёт в файлах, не в чате.
- Кандидаты-находки оформлять с точной ссылкой: файл, таймкод, координаты кадра, скриншот, степень уверенности.
