# scene3d — трёхмерная модель участка, построенная кадрами

Собирает [`docs/nezavisimyy-analiz/model-3d/model-3d.html`](../../docs/nezavisimyy-analiz/model-3d/model-3d.html):
рельеф, полученный плотным стереосопоставлением по кадрам дрона, с ортофотопланом из тех же
кадров и снимками объектов, подвешенными на измеренной лазером дальности.

## Конвейер

```
1. sparse   реконструкция COLMAP по клипу 163855 (52 кадра)
2. привязка по телеметрии, RANSAC-подобие; лазерные точки держатся вне подгонки
3. undistort_images                       CPU, pycolmap
4. colmap patch_match_stereo              GPU, контейнер colmap/colmap:latest
5. stereo_fusion                          CPU, pycolmap -> 1 540 002 точки
6. подгонка плоскости, сетка рельефа, ортофотоплан
7. упаковка в один самодостаточный HTML
```

Шаг 4 — единственный, которому нужен CUDA. `pycolmap` в сборке без CUDA, поэтому он
вынесен в контейнер:

```bash
docker run --rm --gpus all -v "$PWD/out/dense/site/dense:/w" colmap/colmap:latest \
  colmap patch_match_stereo --workspace_path /w --workspace_format COLMAP \
  --PatchMatchStereo.geom_consistency true --PatchMatchStereo.max_image_size 1600
```

21,5 минуты на RTX 4070 Ti SUPER для 52 кадров (104 карты глубины).

## Запуск

```bash
python analysis/scene3d/fuse_dense.py --name site     # слияние карт глубины
python analysis/scene3d/build_scene3d.py              # поверхность, ортофото, scene.json
python analysis/scene3d/pack_scene3d.py               # HTML
python -m pytest analysis/scene3d/tests/
```

Нужны: `numpy`, `scipy`, `opencv-python`, `pycolmap`, `rasterio`, `pyproj`, Python 3.12.

**Про переносимость честно.** `src/drape.py` самодостаточен: кроме numpy, scipy и OpenCV
ему ничего не нужно. `src/scene3d.py` подтягивает соседние модули конвейера обработки
(`georef`, `terrain_prior`, `telemetry`, `stills`), которых в этом репозитории нет, а пути к
данным заданы константами в начале `build_scene3d.py`. То есть код выложен как разбираемый
референс и основа для переноса, а не как готовый к запуску здесь пакет. Готовый результат —
сам HTML, он работает сам по себе.

## Файлы

| файл | назначение |
|---|---|
| `src/drape.py` | подгонка плоскости, сетка рельефа, ортофотоплан, окклюзия, тоновое согласование |
| `src/scene3d.py` | локальная система ENU, привязка, камеры, триангуляция, проверки по лазеру |
| `fuse_dense.py` | слияние карт глубины и привязка плотного облака |
| `build_scene3d.py` | сборка `scene.json` и растров |
| `pack_scene3d.py` | упаковка в самодостаточный HTML, с жёстким лимитом размера |
| `viewer_template.html` | просмотрщик (three.js r128) |
| `tests/` | pytest, 38 тестов |

## Три вещи, на которых легко обжечься

**Система высот.** Всё ведётся в **эллипсоидальных** высотах WGS84. Телеметрия DJI и
лазерный дальномер дают эллипсоидальные, ЦМР Copernicus — ортометрические EGM2008, разница
здесь 33,19 м. Перевод делается ровно в одном месте, на импорте ЦМР.

**Зеркальность.** Тройка `right, up, forward` у камеры левосторонняя
(`right × up = −forward`), рендереру нужна правосторонняя `[right, up, −forward]`. Ошибка
здесь отражает каждый кадр на поверхности, а зеркальный заснеженный склон выглядит ровно
как заснеженный склон. Защита — первый тест в `tests/test_drape.py`: он проецирует облако в
четыре кадра и сверяет взятый пиксель с собственным цветом точки (медиана 14–16) против
зеркального контроля (46–55). Запускайте его перед любыми правками геометрии.

**Вырожденные подмодели.** `scene3d.telemetry_degeneracy` отбраковывает реконструкции,
камеры которых стоят на месте или на одной линии: масштаб у них не определён, подгонка
схлопывает облако и рапортует при этом прекрасную невязку. Подмодель на 164 кадра и 73 871
точку — как раз такой случай: её облако ложится в 108 м от рюкзака.
